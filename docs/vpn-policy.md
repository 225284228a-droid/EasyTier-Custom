# 网段出口 VPN

每条规则将一个目标网段交给一个 EasyTier 出口节点。支持 IPv4、IPv6、默认网段和多个网段分别使用不同出口。规则为空时不会启动客户端，也不需要保存 `[vpn]` 配置块。

规则接在官方出口节点之前：命中规则的目的地址只走该规则的出口，出口失联时丢弃；未命中规则的目的地址按官方 `exit_nodes` 列表处理。出口节点需要开启官方的 `[flags] enable_exit_node`（默认关闭）。

通过 WireGuard 接入 VPN Portal 的 IPv4 客户端继承 Portal 所属网络的 VPN 配置，并跟随规则的热更新及清空。每个客户端独立维护路由排除和出口可达状态，保留自身身份与 ACL；组网及代理子网继续优先，具体出口失联时不会改走宽泛规则。此继承仅处理已进入 Portal 的流量，不扩大生成的 WireGuard `AllowedIPs`，需要由客户端配置将目标网段送入隧道。

```toml
[[vpn.rules]]
cidr = "203.0.113.0/24"
exit = "10.144.144.2"

[[vpn.rules]]
cidr = "2001:db8::/32"
exit = "10.144.144.3"
```

规则可以不写 `exit`：该网段仍被接管，但按官方 `exit_nodes` 列表的顺序选第一个可达出口，出口全部不可达时与官方一致。状态页把这类规则的出口显示为“出口节点列表”。

```toml
exit_nodes = ["10.144.144.2", "10.144.144.3"]

[[vpn.rules]]
cidr = "0.0.0.0/0"
```

出口填写本网络节点的虚拟 IPv4 或 IPv6 地址，不能填写域名或节点代理子网内的普通地址。出口节点须设置 `enable_exit_node = true`。Linux 自动管理所需 forwarding 和 NAT，其他平台沿用现有代理转发能力。

## 匹配与生命周期

- 非空规则列表自动启用客户端。清空规则移除 VPN 捕获，正常组网所需的 TUN 和路由继续运行。
- 最长前缀匹配；重复 CIDR 拒绝加载。具体规则的出口失联不会回退到覆盖它的宽泛规则。
- 指定出口不可达时，匹配流量在 EasyTier 内丢弃，捕获路由保持；出口恢复后继续使用它。
- 虚拟组网、已知远端子网代理、手动组网路由、本机代理子网保留原有路径，即使与 VPN 规则重叠。除此之外没有自动私有地址豁免。
- 仅显式配置的目的网段被接管。DNS 与普通目的流量一样匹配规则；配置 IPv4 出口不会自动阻断或捕获 IPv6。

例如 `0.0.0.0/0` 接管除上述组网/代理网段之外的 IPv4 流量；`::/0` 用于 IPv6。未匹配的目的地址继续使用原有网络路径。

## 平台与状态

桌面仅安装 VPN 出口捕获路由。Linux 每个实例使用一张独立捕获表及 socket 绕过标记，转发自 TUN 的流量不会重新捕获；Windows/macOS 保留原生接口绕过。EasyTier 自身建连与启动 DNS 使用受保护的原生 socket。Windows/macOS 在启用捕获前一起发布系统默认出口与可用接口信息；旧 socket 的接口选择必须仍在默认出口、可用接口集合内。系统默认出口可以是通过其他 VPN 虚拟网卡建立的出口，EasyTier 不强制它必须是物理网卡。绑定到捕获 TUN 或已不可用接口的源地址会明确失败，避免把底层连接重新送回隧道。

Linux 支持同一进程内多个实例及不同网络命名空间。在同一命名空间已有另一进程持有捕获租约时，新客户端明确报告资源冲突，避免相互接管受保护 socket。

Android 使用组网和出口路由的完整 `capture_routes`，通过 `policy_generation` 和实际虚拟 IPv6 地址重配 VPN，保留系统 DNS 与原生 socket 保护。

状态页与 CLI 显示目标网段、单个出口及可达状态，并保留路由状态和启动错误。不再维护 VPN 专用包数、字节数或延迟统计。

出口失联丢弃保证适用于已经进入 EasyTier 的捕获流量；此功能不提供系统级 kill switch。强制绑定其他物理接口或外部删除 TUN/捕获路由的程序不受专用防泄漏机制保护。

## 从旧策略配置迁移

升级前正常停止旧实例，使其释放拒绝表、OUTPUT 防护规则与旧捕获资源，再替换程序。新版本仅回收自己的单表租约，不扫描或迁移旧防护残留。

新配置仅允许 `[vpn]` 的 `rules`，以及每条规则的 `cidr`、`exit`。早期的 `exit_enabled` 仍可读取但不再生效，出口端改用 `[flags] enable_exit_node`。其他旧字段明确报错，不自动转换：

- 将确实需要的旧 `action = "exit"` 规则改写为单个 `exit` 地址，删除 `action`、`exits`、`priority`。
- 删除备用出口、直连和阻断规则，以及 `dns_protect`、`ipv6_protect`、`ignore_private`。不要将它们继续保留在配置中。
- 管理协议使用 `exit_addr` 字段；客户端与内核需同时更新，能力标识为 `config:vpn-subnet-exit-v1`。
