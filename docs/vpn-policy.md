# VPN 规则与路由保护

VPN 客户端由非空规则列表自动启用。清空规则只移除策略接管，正常组网所需的 TUN 继续由原有生命周期管理。默认不提供出口转发；DNS 防泄漏、IPv6 防泄漏、忽略内网地址默认开启。提供出口转发位于高级设置。

新配置直接使用虚拟 IP 列表，不再支持客户端 `enabled`、全局 `fail_mode`、独立出口列表、主出口或备用出口字段。例如：

```toml
[vpn]
exit_enabled = false
dns_protect = true
ipv6_protect = true
ignore_private = true

[[vpn.rules]]
cidr = "0.0.0.0/0"
action = "exit"
exits = ["10.144.144.2", "10.144.144.3"]
priority = 0

[[vpn.rules]]
cidr = "203.0.113.0/24"
action = "direct"
priority = 0
```

每条规则只有 `cidr`、`action`、有序 `exits` 和 `priority`。`exit` 按列表顺序使用首个可用节点，全部不可用时阻断；节点恢复后重新优先使用靠前的出口。`direct` 始终直连，`block` 始终阻断。先选最长前缀，再选较低优先级，最后按列表顺序选唯一规则；所选规则失效不会回退到覆盖它的其他规则。

包处理、桌面系统路由和 Android 捕获路由使用同一个 CIDR 编译结果。规则被拆成互不重叠的区域，默认路由与显式 `/1` 规则遵守相同优先级。出口未知或全部失效不会撤掉捕获路由。状态页围绕规则显示有序出口、当前出口和统计；完全被覆盖或豁免的规则没有当前出口。

组网 IPv4/IPv6 网段、已知远端子网代理和手动组网路由始终保留 overlay 路径；本地提供的子网代理保留物理路径。链路失联或路由公告过期不会取消这些保护。收到更新的网段公告时更新对应保护，实例停止时释放。忽略内网开启时，`10/8`、`172.16/12`、`192.168/16`、`100.64/10`、`127/8`、`169.254/16`、`fc00::/7`、`::1/128`、`fe80::/10` 绕过全部 VPN 动作，包括明确阻断；关闭它仍保留组网和子网代理保护。

存在有效出口区域时，公共 DNS 根据其目标地址匹配规则；没有可执行出口且没有明确直连规则时阻断。IPv4 出口开启 IPv6 防泄漏时，未被 IPv6 规则和上述豁免覆盖的 IPv6 区域阻断。EasyTier 自身建连使用独立的受保护解析和 socket，出口失效时仍可重连。

Linux 使用独立 VPN 捕获表、拒绝兜底表和 socket 绕过标记，并通过独立的 iptables/ip6tables OUTPUT 规则链阻断捕获网段中走向其他接口的未保护流量。绑定物理接口也不能绕过保护；受保护 socket 跳过两张表和 OUTPUT 防护，TUN 输入后的转发不受 OUTPUT 链影响。只有强制 overlay 网段保留本地投递，明确 Exit/Block 区域没有额外的本地地址豁免。标记避开现有配置与外部 fwmark 规则，无可用标记、安全路由优先级或所需防火墙能力时拒绝接管。Windows/macOS 使用原生接口作用域。接管前保护现有 socket，新 socket 在首次联网前保护。策略启用失败通过 `activation_error` 状态报告。

Linux 保留 IPv6 链路邻居探测和路由器发现所需的 ICMPv6 133–136 控制报文，仅允许 code 0、hop limit 255；路由器发现还限制链路本地/链路组播目标，路由器公告源必须为链路本地地址。内核邻居探测不能依赖应用 socket 的标记。此例外不放行 UDP、DNS 或公网 Echo 流量。

Linux 出口转发按网络命名空间共享引用，首次启用保存 `all/default`、各接口 forwarding 和存在时的 `force_forwarding`，最后一个使用者停止后恢复。NAT 只清理本次创建的规则，并按实际安装网段处理更新和失败回滚。停止流程等待路由与转发清理完成后销毁网卡。

Android 从 `capture_routes` 和 `policy_generation` 应用 Rust 的完整路由结果，使用实际 IPv6 地址与 DNS 列表，并按真实包名排除自身。热更新保留旧接口，建立新接口，等待 Core 安装确认后释放旧描述符；安装失败保留捕获接口，过期 generation 不提交。
