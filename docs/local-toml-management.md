# 本地 TOML 与网络管理

本地配置节点以磁盘文件为权威。设备管理和按网络管理通过在线 RPC 修改这些文件及运行状态，云端配置镜像用于展示，不作为整目录恢复来源。

## 文件生命周期

- `--config-dir`（或 `ET_CONFIG_DIR`）指定配置目录；默认 `config.d` 相对于进程工作目录，启动日志会打印实际绝对路径。
- 原生内核监听目录事件，约 200ms 合并编辑器的连续写入和原子替换事件；30 秒完整扫描用于补偿丢失通知。无法安装监听器时改用 1 秒扫描。
- 新增有效 TOML 默认启动；修改启用中的配置会应用新文档；删除文件停止对应实例并清除启停状态、目录登记和云端镜像条目。
- 配置目录模式在最后一个网络被删除或停用后继续监听；重命名配置保留实例和启停状态。
- 网页明确停用的实例仍保持停用，文件修改更新其保存内容；删除后重新添加视为新配置并默认启动。
- 仅注释或格式变化不重启。解析失败、重复 UUID 或宿主应用失败不会替换可用的旧运行配置；修复文件后重试。启用失败会保留用户文件。
- 本地文件的环境变量和只读权限不阻止本地运行，但继续限制网页写入和敏感配置展示。缺少 UUID 的旧文件复用其目录登记中的运行身份，不在每次扫描时创建新实例。

## 网页操作

文件事件、设备管理、按网络管理共用节点的进程协调锁和宿主生命周期钩子。RPC 已经完成的写入不会被监听器重复应用；明确的 `PersistOnly` 保持“仅保存”，后续手工修改仍会自动应用。版本 CAS 继续阻止过期网页编辑覆盖新文件。

按网络管理现在可以加入本地配置节点。首次交付创建并启动对应 TOML，更新和删除只操作该控制台交付记录中的网络实例。离线交付和删除保留在 SQLite 日志中，节点恢复后重试；错误通过成员状态展示。

成功交付的相同期望配置不会被定时重新推送。因此手工改删文件不会被旧云端配置恢复。之后明确发布的网络变更若与本地文件版本冲突，会报告冲突并保留文件。节点重启仅在原始文件、运行配置、权限和启停状态均等价时恢复交付基线；安全模式更新保留节点已有密钥。

## 验证

回归覆盖真实磁盘事件的新增、修改、原子替换、重命名和删除；停用状态清理；仅保存后的手工编辑与回退；环境配置、重复 UUID 和宿主失败回退；两套控制台镜像、按网络管理创建/更新/删除、离线交付及本地编辑冲突。
