# 网络管理：去中心识别 + 核心设置统一下发

## 模型

网络页不区分“中心托管”和“去中心批量”两种模式，只有一种网络：

- **网络 = 设备上同一网络名的实例。** `frontend/src/modules/networkDiscovery.ts` 扫描在线
  设备的运行和已停止实例，按 `network_name` 分组；分组键 `name:<网络名>` 与拓扑地球仪
  的节点身份相同，所以网络页和地球仪看到的是同一组节点。中心模式下还会合并控制台记住的
  实例（`GET /api/v1/mesh/members`）和控制台自己的网络记录（`GET /api/v1/mesh/networks`），
  所以离线成员、待补发、临时设备，以及还没有成员的新网络也能显示。
- **控制台统一管理“不一致就失联”的核心设置**：网络名、网络密码、安全模式开关、关闭
  加密、加密算法。依据：握手校验网络名和密码摘要（`peer_conn.rs`），安全模式决定握手方式；
  非安全模式下加密器按实例由密码派生（`peer_manager.rs`），不加密的一端会拒收加密包
  （`tunnel/encrypt/mod.rs`）。压缩靠每个包的标记、流量伪装两端协商，不一致不会失联。
- **三个名字各管各的**：
  - **网络名称**（`network_name`）是组网身份，与密码一起决定节点能否互联；网络页按它识别网络。
  - **网络密码**（`network_secret`）参与握手校验，不一致就失联。
  - **网络显示名称**只用于显示：写入每个成员配置的 `instance_name`（`api_manage.proto` 字段
    50086，能力 `config:instance-name-v1`），设备上显示配置时用它覆盖原来显示的名称；留空则显示
    网络名称。实例 ID 和 `default` 是占位名，不算显示名称。它不影响组网，但和核心设置一起
    下发、一起补发。官方内核总是用网络名称命名实例，所以显示名称不会写给官方节点。
- **高级设置增量批改**：功能开关和压缩算法、MTU、流量伪装、并行连接数可以整网批量修改，
  只写用户改动过的项（见下文）。
- **设备专属的设置不统一编辑**：虚拟 IPv4、DHCP、主机名、子网代理、出口节点、出口网段规则、
  自定义路由、SOCKS5、端口转发等都只能到单台设备里改。初始节点和监听地址只作为“新设备
  预下发”，不会修改已有成员。
- **ACL 已移除**：网络级 ACL 依赖成员登记表，每个成员的 ACL 又依赖全体成员，与“只补一次”
  冲突，多控制台还会互相覆盖。设备文件里已有的 ACL 保持原样。

## 网络页面

每个网络一个页面（`frontend/src/components/network/`），左侧子导航：

| 子页面 | 内容 |
| --- | --- |
| 概览 | 设备、运行、拓扑节点、连接数，核心设置摘要，只显示本网络的地球仪 |
| 成员 | 卡片（默认）/表格；批量启动、停止（跳过锁定成员）；加入设备；点设备在当前页打开设备管理 |
| 网络设置 | 核心设置：显示名称、网络名称、密码、安全模式、加密；删除网络 |
| 高级设置 | 功能开关和传输参数的增量批改，每项显示当前成员的取值分布 |
| 预下发配置 | 新设备自动加入开关；初始节点、监听地址、开关和参数的初始值 |
| 临时设备 | 临时设备、凭证、接入设置（虚拟子网、初始节点） |

这六个子页面对任何识别出的网络（包括完全去中心的网络）都可用。唯一的例外是控制台启动时
加了 `--webhook-url`：此时设备的身份校验和配置交给外部系统管理，控制台不运行自己的管理逻辑，
网络设置、高级设置、预下发和临时设备四页不可用，只有概览和成员。所有列表默认卡片视图，可切换表格，选择保存在浏览器里。

设备管理从任何页面打开都浮在当前页上（设备放在 URL 查询参数 `device`/`instance` 里），关闭
后停留在原页面原位置。

## 新建网络与加入设备

“新建网络”只有网络名称必填（`POST /api/v1/mesh/networks`）：密码留空由控制台生成，可选显示
名称、安全模式、预下发（初始节点默认填控制台接入点地址，监听地址用默认值）和立即加入的设备。
网络先作为控制台的记录存在（表 `mesh_networks`：核心设置、预下发、自动加入），没有成员也会
显示。

加入设备（成员页“加入设备”、自动加入、新建时选设备，`central_network/mesh_network.rs`
的 `join`）：按网络当前核心设置 + 预下发创建一份新配置并启动，虚拟 IP 用 DHCP；已经是成员
的设备不动。网络当前核心设置取控制台自己最后写入的那份，若某成员的 `network_sync_at` 更新
（另一个控制台改过）则取该成员的。官方节点把配置存进控制台保存的配置，上线即生效。

**新设备自动加入**：打开开关时，控制台把当时已知的设备都记为“已见过”（表
`mesh_auto_joins`）；之后第一次连上的设备在下一个对账周期按预下发加入一次，无论成功与否
都不再重试。

## 核心设置下发（`central_network/core_sync.rs`）

1. 每个对账周期（5 秒）读取在线、支持 revision 的设备的配置目录（会话缓存，节点宣告变更
   时才重新读取），记录每个实例的核心设置、高级设置和时间戳（表 `mesh_observations`）。
   离线设备保留最后一次记录，所以离线成员仍能被找到。
2. 修改核心设置时（`POST /api/v1/mesh/core`），控制台按网络名找出全部成员（锁定的也包括，
   核心设置不一致会失联）：
   - 在线成员：读取最新版本，只写与目标不同的核心字段，带 revision 写入，期间文件被别人
     改过则报冲突、不覆盖；
   - 离线成员：记一条补发记录（表 `mesh_core_replays`），包括修改前的核心值和时间戳、这次
     的改动和时间戳。同一成员多次错过修改时合并成一条，按字段以后者为准。
   控制台自己的网络记录同步更新，改名时记录跟着改名。
3. 成员重新上线后的第一个对账周期补发一次，**无论是否发出记录都删除**。手动修改和其他
   控制台的修改不区分来源，只看先后：期间在设备上手动改过的照样被覆盖（手动修改不改时间戳，
   算作更早）；只有节点时间戳新于这次修改（另一个控制台更晚写过）时才不发。
   补发时使用这个控制台能看到的同网络最新值（在线成员里时间戳更新的那份优先）。
4. 补发之后本地再改，控制台不会改回。

官方节点（以及不带配置目录运行的内核）没有自己的配置目录，配置由控制台保存，节点在线时由
控制台下发。对这类成员直接**强制覆盖**控制台保存的那份配置，保持原来的启停状态，在线的立即
生效，离线的在重新连上时由控制台下发。官方节点只能连一个控制台，不存在竞争，所以不需要
时间戳和“修改前的值”比较。

## 高级设置增量批改（`central_network/advanced.rs`、`mesh_network.rs`）

可批改的字段在 `advanced.rs` 的 `FIELDS`（前端镜像在 `frontend/src/modules/meshAdvanced.ts`）：
延迟优先、IPv6、KCP/QUIC、P2P 与打洞类、UPnP、中继类、Magic DNS、多线程、广播中继、冗余连接
清理、并行连接开关，以及压缩算法、MTU、流量伪装、并行连接数。排除出口节点转发、不创建网卡、
smoltcp、绑定物理网卡、系统转发（设备专属），私有模式（保持默认开启），加密（核心设置）。

`POST /api/v1/mesh/advanced` 只带用户改动过的项（`null` 表示恢复默认）：

- **锁定的成员跳过**，结果为“已锁定”；
- 在线成员只写与目标不同的项，需要能力的字段（流量伪装、并行连接）在不支持的节点上略过；
- 每次批改在节点上写 `advanced_sync_at`（`api_manage.proto` 字段 50087，能力
  `config:advanced-sync-v1`，UTC 毫秒），与核心设置的 `network_sync_at` 分开，避免一类设置
  的修改挡住另一类的补发；
- 离线成员记补发（表 `mesh_advanced_replays`，含这次的时间戳）；上线后补发一次，规则同核心
  设置：期间的手动修改照样覆盖，只有另一个控制台更晚的批改会保留；多次错过时按字段合并，
  后者为准；
- 官方节点和核心设置一样强制覆盖控制台保存的配置。

## 锁定

设备管理里每份配置的“高级设置”标题栏（展开/收起按钮旁）有锁定按钮。锁定状态**只存在本
控制台**（表 `mesh_locks`），其他控制台看不到。锁定后本控制台的批量编辑不改它的高级设置、
功能开关和启停状态；核心设置照常下发。

## 删除网络

`DELETE /api/v1/mesh/networks/{name}` 只删除控制台的数据：网络记录、预下发、自动加入记录，
同名中心记录（临时设备的配置随之删除，凭证吊销）。成员设备上的配置保留并**暂停**：在线的
立即暂停，离线的记一条暂停补发（表 `mesh_pause_replays`），下次上线时暂停一次；官方节点
在控制台保存的配置上标记停止；锁定的成员保持原状。

## 多控制台

一个内核可以同时连多个控制台（`--config-server` 逗号分隔，`easytier/src/core.rs`），这些
连接共用同一个实例管理器和配置目录，所以各控制台读到的是同一份文件和版本。

- **识别自动一致**：网络来自设备文件，A 改过的值 B 下一个周期就能看到。
- **先后顺序**：设备配置字段 `network_sync_at`（`api_manage.proto` 字段 50085，TOML 顶层
  键，能力 `config:network-sync-v1`）记录最后一次核心设置修改的 **UTC Unix 毫秒**。它是绝对
  时刻，与控制台所在时区无关；为防止机器时钟偏差，新时间戳取“当前 UTC 毫秒”和“已见最大
  时间戳 + 1”中较大者。内核运行时不使用它；官方节点由唯一的控制台强制覆盖，不需要它。
- 高级设置的批改另有 `advanced_sync_at`（字段 50087），规则相同。两类设置各用一个时间戳，
  补发只比较先后，最新的修改胜出；手动修改没有时间戳，视为比任何控制台的修改都早，所以
  照样被补发覆盖。
- 预下发、自动加入和锁定都只属于各自的控制台。

## 临时设备

临时设备的配置由控制台整份覆盖下发，使用凭证而不是网络密码接入，需要安全模式。网络第一次
添加临时设备时，控制台按网络的核心设置自动建一条中心记录（有接入点时走接入点，否则用预下发
的初始节点），之后网络名、密码、安全模式和加密跟随核心设置。用户看不到“中心网络”这一层。

- 迁移 `m20261102_000014_mesh_core_sync` 先删除永久成员的下发记录再删除成员，设备上的实例保留
  （若只删成员，下发记录会把它们当成删除）。
- 临时设备凭证要由持有网络密码的节点广播才被全网信任（`peer_ospf_route.rs`）。接入点实例
  本身带有凭证；此外控制台把凭证写入在线永久成员的 `managed_credentials`，只增删自己写过的
  那些（表 `mesh_credential_deliveries`），不会冲掉其他控制台的凭证。

  `service`（只填名称建网、预下发加入、锁定跳过与离线补发、删除暂停、自动加入只认新设备、

- `cargo test -p easytier-proto`：字段编号清单。
